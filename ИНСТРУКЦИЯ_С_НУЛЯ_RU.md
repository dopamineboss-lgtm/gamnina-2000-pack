# GitHub для Gamnina 2000 — инструкция буквально с нуля

## Что уже сделано

Ничего собирать, раскладывать или программировать не требуется. Эта папка уже является локальным Git-репозиторием, внутри лежат клиентская сборка, генератор манифеста, маленький загрузчик и обновляемое ядро красивого лаунчера.

Зафиксированные значения:

- GitHub-аккаунт: `dopamineboss-lgtm`;
- имя репозитория: `gamnina-2000-pack`;
- ветка: `main`;
- видимость: **Public**;
- адрес манифеста: `https://raw.githubusercontent.com/dopamineboss-lgtm/gamnina-2000-pack/main/manifest.json`.

Лаунчер уже собран именно с этим адресом. Не меняйте логин, имя репозитория или ветку после публикации — иначе потребуется пересборка EXE.

## Первый и единственный сложный раз

1. Создайте или откройте аккаунт `dopamineboss-lgtm` на GitHub.
2. Установите **GitHub Desktop** с `https://desktop.github.com/` и войдите в этот аккаунт.
3. В GitHub Desktop нажмите **File → Add local repository**.
4. В поле пути выберите целиком папку `1 - GITHUB - gamnina-2000-pack` и нажмите **Add repository**.
5. Вверху нажмите **Publish repository**.
6. Проверьте поля:
   - Name: `gamnina-2000-pack`;
   - Description: `Gamnina 2000 Minecraft 1.12.2 modpack updates`;
   - **снимите галочку `Keep this code private`**;
   - Organization: `None`.
7. Нажмите **Publish Repository** и дождитесь завершения первой отправки. Первая отправка весит около 250 МБ, поэтому она может идти несколько минут.
8. Откройте в браузере:
   `https://raw.githubusercontent.com/dopamineboss-lgtm/gamnina-2000-pack/main/manifest.json`
   Если виден большой JSON с `schemaVersion`, `version` и `files`, канал обновлений работает.

Почему Public обязателен: в приватный репозиторий друзьям понадобился бы GitHub-токен. Токены нельзя вшивать в лаунчер — любой человек смог бы его вытащить.

## Что отправить друзьям

После первого Push можно дать прямую ссылку:

`https://raw.githubusercontent.com/dopamineboss-lgtm/gamnina-2000-pack/main/launcher/Gamnina2000Launcher.exe`

Друг сохраняет EXE размером около 180 КБ в любую папку и запускает. На первом запуске он:

1. установит свою рабочую копию в `%LOCALAPPDATA%\Gamnina2000\launcher`;
2. создаст на рабочем столе ярлык **Gamnina 2000** с нормальной иконкой;
3. скачает и проверит по SHA-256 основное ядро лаунчера размером около 73 МБ;
4. запустит красивый лаунчер Gamnina 2000;
5. попросит официальный вход Microsoft;
6. локально подготовит Java 8;
7. скачает клиентскую сборку с GitHub и проверит каждый файл;
8. установит Minecraft 1.12.2 и Forge 14.23.5.2859;
9. подключит к серверу `199.231.161.226:50202`.

Исходный EXE после этого можно удалить или оставить: ярлык всегда запускает установленную копию из `%LOCALAPPDATA%`, поэтому перенос исходного файла ярлык не сломает.

Windows может показать предупреждение SmartScreen, потому что EXE не подписан платным сертификатом. Имя и версия файла можно проверить через «Свойства → Подробно».

## Как выпускать обновления потом

Когда Codex добавит или удалит мод, конфиг, ресурспак или шейдер, изменения будут внесены в `client/`, а `manifest.json` будет пересобран. Вам останется:

1. открыть GitHub Desktop;
2. убедиться, что выбран репозиторий `gamnina-2000-pack` и ветка `main`;
3. слева увидеть список изменений;
4. в поле **Summary** написать, например, `Update modpack`;
5. нажать **Commit to main**;
6. нажать **Push origin**.

После Push лаунчеры при следующем открытии получат новый манифест, сравнят SHA-256 и докачают только изменившееся. Перед непосредственным запуском игры проверка выполняется ещё раз, поэтому давно открытый лаунчер тоже не запустит устаревшую сборку. Иногда файлам GitHub требуется несколько минут, чтобы обновиться во всех кэшах; лаунчер специально отправляет запрос без локального кэша.

Если вы меняли `client/` самостоятельно:

1. дважды нажмите `1 - ОБНОВИТЬ МАНИФЕСТ.cmd`;
2. затем `2 - ПРОВЕРИТЬ ПАПКУ.cmd`;
3. только после зелёной проверки делайте Commit и Push.

Удаление тоже автоматическое: уберите файл из `client/`, запустите генератор, и его путь попадёт в `deletedPaths` манифеста.

## Что GitHub обновляет, а что нет

GitHub-папка отвечает за клиентские `mods`, `config`, ресурсы, шейдеры, шрифты и список сервера. Папка мира и серверные моды не загружаются оттуда на хостинг автоматически.

Для сервера используйте соседнюю папку `2 - SERVER - UPLOAD TO HOSTING`: её содержимое загружается в корень Forge-сервера через панель или файловый менеджер хостинга.

Код и дизайн основного лаунчера тоже обновляются автоматически: маленький bootstrap сверяет `launcher/channel.txt`, размер и SHA-256 файла `Gamnina2000Core.exe`. Ручная повторная загрузка понадобится только в крайне редком случае изменения самого 180-КБ bootstrap-файла; обычные обновления интерфейса, логики, модов и конфигов приходят автоматически.

## Чего не делать

- не ставьте репозиторий Private;
- не переименовывайте `main`, репозиторий или GitHub-аккаунт;
- не загружайте один общий ZIP сборки — обновления снова станут огромными;
- не добавляйте пароли, токены, `saves`, серверный мир или данные Microsoft;
- не удаляйте `manifest.json` и `deleted-paths.txt`;
- не используйте Git LFS для этой версии: самый большой файл меньше 100 MiB, а LFS добавит квоты и лишнюю настройку.

## Если что-то не работает

- `404` по ссылке манифеста: репозиторий ещё не опубликован, имеет другое имя, приватный или ветка называется не `main`.
- Лаунчер пишет, что SHA-256 не совпал: файл изменили, но не запустили `1 - ОБНОВИТЬ МАНИФЕСТ.cmd` перед Push.
- GitHub не принимает Push: проверьте, нет ли нового файла размером 100 MiB или больше; скрипт проверки тоже это обнаружит.
- GitHub временно недоступен: после хотя бы одного успешного запуска лаунчер использует сохранённый проверенный манифест и уже скачанные файлы. Новые отсутствующие файлы без интернета, естественно, скачать нельзя.
